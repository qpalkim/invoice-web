# 견적서 웹 확인 서비스 개발 로드맵 (고도화)

MVP로 완성한 견적서 확인 서비스를 실제 운영에 맞게 다듬는 고도화 로드맵.

## 개요

**견적서 웹 확인 서비스**의 MVP(Phase 1~4, Task 001~012)는 2026-08-08 기준으로 모두 완료되었습니다. 노션 견적서 동기화, 상세 확인 및 공유 링크 생성, 클라이언트 비로그인 열람, PDF 다운로드까지 핵심 사용자 여정이 실제 데이터로 동작합니다.

이 문서는 MVP 이후 **고도화 단계**만을 다루는 로드맵입니다. MVP 단계의 완료된 Task는 다시 나열하지 않으며, 아래 참고 문서에서 확인할 수 있습니다.

- 관련 문서: [PRD](./PRD.md)
- MVP 완료 로드맵(아카이브): [ROADMAP_v1.md](./roadmaps/ROADMAP_v1.md)

이번 고도화 단계에서 다루는 핵심 개선 사항:

- **관리자 레이아웃 고도화**: 단순 헤더 구조를 사이드바/대시보드형 관리자 레이아웃으로 재구축하고 그 안에서 견적서 목록을 표시
- **목록 공유 링크 복사**: 상세 페이지에만 있던 공유 링크 복사 기능을 목록의 각 행/카드에서도 바로 사용할 수 있도록 확장
- **다크모드 지원**: 이미 구현된 `ThemeProvider`/`ThemeToggle`을 실제 페이지에 노출하고, 전체 페이지의 다크모드 스타일을 점검·보정

## 개발 워크플로우

1. **작업 계획**
   - 기존 코드베이스를 학습하고 현재 상태를 파악
   - 새로운 작업을 포함하도록 `ROADMAP.md` 업데이트
   - 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**
   - `/tasks` 디렉토리에 새 작업 파일 생성
   - 명명 형식: `XXX-description.md` (예: `013-admin-sidebar-layout.md`)
   - 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
   - API/비즈니스 로직 및 UI 상호작용 작업 시 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 테스트 시나리오 작성)

3. **작업 구현**
   - 작업 파일의 명세서를 따름
   - UI 상호작용 및 기능 변경 구현 시 Playwright MCP로 테스트 수행 필수
   - 각 단계 후 작업 파일 내 진행 상황 업데이트
   - 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**
   - 로드맵에서 완료된 작업을 ✅로 표시

## 개발 단계

### Phase 5: 관리자 레이아웃 고도화

- ✅ **Task 013: 관리자 사이드바/대시보드 레이아웃 구조 구축**
  - 현재 `src/app/invoice/layout.tsx`가 감싸는 단순 `AdminHeader`(로고 + 링크 1개)를 대체할 사이드바형 관리자 레이아웃 컴포넌트 신설 (`src/components/layout/admin-sidebar.tsx` 등)
  - 사이드바에 "견적서 목록" 등 관리자 메뉴 항목과 현재 라우트 활성 스타일(`usePathname`) 적용
  - 데스크톱은 고정 사이드바, 모바일은 `Sheet`/드로어 등으로 접었다 펼 수 있는 반응형 구조로 구현
  - 상단 바에는 서비스 타이틀/로고와 (Task 016에서 연동할) 테마 토글 자리 확보
  - `src/app/invoice/layout.tsx`를 신규 레이아웃 컴포넌트로 교체하고 `/invoice`, `/invoice/[id]` 양쪽에서 정상 렌더링되는지 확인
  - Playwright MCP 테스트: 데스크톱(1280px)/모바일(390px) 뷰포트에서 사이드바 렌더링 및 모바일 드로어 열기/닫기 동작 확인, 사이드바 메뉴 클릭 시 라우트 이동 확인

- ✅ **Task 014: 견적서 목록 페이지 신규 레이아웃 통합 및 대시보드 UI 고도화**
  - `src/app/invoice/page.tsx`를 Task 013의 신규 관리자 레이아웃 안에서 자연스럽게 보이도록 여백/타이포그래피 조정 (`max-w-3xl` 제약을 대시보드 폭 기준으로 재검토)
  - 목록 상단에 총 견적서 수, 미열람 건수 등 간단한 요약 카드(옵션) 배치로 대시보드 성격 보강
  - 기존 데스크톱 테이블 뷰 / 모바일 카드 뷰 반응형 동작 유지 검증
  - Playwright MCP 테스트: 신규 레이아웃 내에서 목록 데이터(견적서 번호·클라이언트·금액·열람 여부)가 정상 표시되는지, 견적서 클릭 시 상세 페이지로 정상 이동하는지 확인

### Phase 6: 목록 공유 링크 복사 기능

- ✅ **Task 015: 견적서 목록에서 공유 링크 즉시 복사 기능 구현**
  - `src/app/invoice/[id]/copy-share-link-button.tsx`의 `CopyShareLinkButton`을 목록 컨텍스트에서도 재사용 가능하도록 공용 위치(`src/components/`)로 이동 또는 `variant`/`size`/아이콘 전용 모드 등 props 확장
  - 데스크톱 테이블 뷰의 각 행에 복사 아이콘 버튼 추가 (행 클릭 시 상세 이동과 이벤트 충돌 방지 - `stopPropagation` 등 처리)
  - 모바일 카드 뷰의 각 카드에도 동일한 복사 버튼 배치
  - 클릭 시 `sonner` 토스트로 성공/실패 피드백 노출 (기존 상세 페이지와 동일한 UX 유지)
  - Playwright MCP 테스트: 목록 페이지에서 각 행/카드의 복사 버튼 클릭 시 상세 페이지로 이동하지 않고 토스트가 노출되는지 확인, 데스크톱/모바일 두 뷰 모두에서 버튼 동작 확인, 클립보드 API를 모킹해 복사된 URL이 `/q/{quoteId}` 형식인지 검증

### Phase 7: 다크모드 지원

- **Task 016: 다크모드 테마 토글 UI 노출 (관리자/공개 페이지)**
  - 이미 구현된 `ThemeToggle`(`src/components/theme-toggle.tsx`)을 Task 013의 관리자 레이아웃 상단 바에 연결
  - 공개 페이지(`src/app/q/[shareToken]/page.tsx`)에도 헤더 영역을 신설하거나 기존 상단에 테마 토글 노출 (클라이언트가 비로그인으로 접근하는 페이지이므로 최소한의 UI로 배치)
  - 새로고침 시 테마가 깜빡이지 않도록 `ThemeProvider`의 `attribute`/`defaultTheme`/`enableSystem` 설정과 루트 레이아웃(`src/app/layout.tsx`)의 `suppressHydrationWarning` 적용 상태 점검
  - Playwright MCP 테스트: 라이트/다크/시스템 각 옵션 클릭 시 `html` 요소의 `class`/`data-theme` 속성 변경 확인, 새로고침 후 선택한 테마가 유지되는지 확인

- **Task 017: 전체 페이지 다크모드 스타일 점검 및 보정**
  - 견적서 목록(`/invoice`), 상세(`/invoice/[id]`), 공개(`/q/[shareToken]`) 페이지의 색상 대비를 다크모드에서 점검 (텍스트/배경/보더/뱃지/카드 등 하드코딩된 색상값 여부 확인)
  - PDF 다운로드 버튼, 공유 링크 복사 버튼, `EmptyState`/`ErrorState`, `not-found`/`global-error` 페이지 등 공용 컴포넌트의 다크모드 대응 확인
  - PDF 미리보기/생성 자체는 `@react-pdf/renderer`로 별도 렌더링되어 다크모드 영향이 없음을 확인하고, 다운로드 버튼 등 트리거 UI만 다크모드 스타일 점검 대상으로 명확히 함
  - Tailwind v4 다크모드 유틸리티(`dark:` variant) 누락 구간을 찾아 보정
  - Playwright MCP 테스트: 다크모드 전환 후 목록/상세/공개/404/에러 페이지 각각을 스크린샷으로 캡처해 텍스트 가독성 및 레이아웃 깨짐 여부 육안 확인

### Phase 8: 통합 검증

- **Task 018: 고도화 기능 통합 테스트**
  - Playwright MCP로 사이드바 레이아웃 → 견적서 목록 → 목록에서 공유 링크 복사 → 상세 페이지 → 공개 페이지 → PDF 다운로드까지 이어지는 전체 플로우를 다크모드/라이트모드 각각에서 재검증
  - 모바일(390px)/데스크톱(1280px) 두 뷰포트에서 사이드바 드로어, 목록 복사 버튼, 테마 토글이 함께 정상 동작하는지 확인
  - 회귀 테스트: 기존 MVP 핵심 플로우(목록 → 상세 → 공유 링크 → 공개 페이지, Task 008-1 대응)가 레이아웃 변경 이후에도 깨지지 않았는지 확인
  - `npm run check-all`, `npm run build`로 최종 빌드 검증
